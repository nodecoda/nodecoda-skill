Distribution repository for **AI agent skills** that teach coding agents (Claude Code, Codex CLI, Gemini CLI, Cursor, ...) how to author NodeCoda workflows and use the NodeCoda MCP service.

## What is NodeCoda?

NodeCoda is an AI-native workflow engineering platform. Source-of-truth is NodeCoda Source (`.ncoda`); target artifacts (Dify Workflow YAML) are generated by `nclang-compile` via the NodeCoda MCP service.

The companion product is at **[nodecoda/nodecoda](https://github.com/nodecoda/nodecoda)**. This repo exists to ship the **agent-facing knowledge** that lets any AI tool integrate cleanly with that product.

## Install

### Option A — manual (works today)

```bash
# Claude Code
git clone https://github.com/nodecoda/nodecoda-skill.git
cp -R nodecoda-skill/skills/nodecoda-workflow ~/.claude/skills/

# Codex CLI
cp -R nodecoda-skill/skills/nodecoda-workflow .codex/skills/

# Any agent that follows the Claude Code skill convention
cp -R nodecoda-skill/skills/nodecoda-workflow <skill-search-path>/nodecoda-workflow
```

### Option B — npx (live)

```bash
npx -y @nodecoda/skill add nodecoda-workflow
```

One npm package (`@nodecoda/skill`) does both: install the skill
(`add`/`install`) and serve the MCP server zero-install (`mcp`). See
`docs/installation.md` for targets and the MCP wiring.

## 项目化工作流（Project Mode）

创建正式、可版本化、可共享的 Dify 工作流时使用项目模式。一个工作流 = 一个项目目录，`.ncoda` 源码可反复编译。

### 快速开始

```bash
# 探测当前目录是否已是项目
node scripts/project.mjs resolve

# 新建项目（默认 target_profile=dify-1.16-graphon-0.6）
node scripts/project.mjs init ./my-flow --project my-flow --mode workflow

# 状态流转（agent 在各阶段调用）
node scripts/project.mjs set-state ./my-flow DESIGNED
node scripts/project.mjs set-state ./my-flow SOURCE_READY
node scripts/project.mjs set-state ./my-flow BUILDING --build-id job_x
node scripts/project.mjs set-state ./my-flow SUCCEEDED --sha256 <hash>

# 校验项目结构
node scripts/validate-project.mjs ./my-flow

# 保存编译产物（SUCCEEDED 后）
node scripts/save-build.mjs <build_id> --source src/my-flow.ncoda --out builds
```

### 项目目录

```
my-flow/
├── nodecoda.yaml        # 清单
├── nodecoda.state.json  # 状态机状态
├── design.md            # 需求分析
├── src/my-flow.ncoda    # 源码（事实源）
└── builds/<build_id>/   # 编译历史（gitignore）
```

### 版本化与共享

`src/`、`nodecoda.yaml`、`design.md` 入 git；`builds/` 默认 gitignore（可复现性由 `build_id` + `source_sha256` 保证）。共享项目目录即可重新编译。

### 轻量模式

只验证 `.ncoda` 片段或排查单点时，可不建项目，直接对话内 build；需声明"这是临时验证"。

完整协议见 `skills/nodecoda-workflow/references/project-workflow.md`。

## Versioning

This repo's `skills/*` are versioned **independently** of NodeCoda core. Each skill has its own `manifest.json` with:

- `version` — semantic version of the skill
- `min_nodecoda` — minimum NodeCoda core version required
- `target_profile` — Dify profile this skill was written against (e.g. `dify-1.16-graphon-0.6`)

The release pipeline in `.github/workflows/release.yml` cross-checks the skill's `target_profile` and `mcp_tools` against the live NodeCoda codebase before publishing.
